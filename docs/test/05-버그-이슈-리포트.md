## 3. 상세

### BUG-001 형식이 잘못된 쿼리 파라미터에 500 응답 — ✅ 수정

| 항목 | 내용 |
|---|---|
| 재현 조건 | `GET /v1/diet/records?date=2026-13-40` 또는 `GET /v1/statistics/daily?date=yesterday` (로그인 상태) |
| 기대 결과 | 400 `VALID_011` "입력값의 범위 또는 형식을 확인해주세요." |
| 실제 결과 | **500 `SERVER_001`** "일시적인 오류가 발생했습니다." 서버 로그에 ERROR 스택 출력 |
| 영향 범위 | 날짜·숫자 타입 쿼리 파라미터를 받는 모든 API (식단 조회, 캘린더, 통계, 피드백, 주변 매장, 게시글 목록, 음식 검색) |
| 원인 | Spring이 문자열을 `LocalDate`/`int`로 바꾸다 실패하면 `MethodArgumentTypeMismatchException`을 던지는데, `GlobalExceptionHandler`에 이 예외 처리가 없어서 마지막 `Exception` 처리기(500)로 넘어감 |
| 수정 내역 | [`GlobalExceptionHandler.java`](../../backend/src/main/java/com/bapmeokja/api/common/exception/GlobalExceptionHandler.java): 400 처리 대상에 `MethodArgumentTypeMismatchException` 추가 |
| 회귀 테스트 | 단위: `GlobalExceptionHandlerTest.malformedTypedQueryParameterReturnsBadRequest` (MockMvc로 실제 변환 경로 검증) · 통합: IT 케이스 3건 추가 (`year=abc`, `page=first`, `lat=north`) |
| 확인 | 통합 테스트 1차 128/130 → 최종 133/133, 서버 500 응답 0건 |

### BUG-002 만료된 refresh token이 DB에 계속 쌓임 — ✅ 수정

| 항목 | 내용 |
|---|---|
| 재현 조건 | 로그인할 때마다 `refresh_tokens`에 행이 하나씩 추가됨. 로그아웃하지 않고 앱을 지우거나 기기를 바꾸면 그 행은 만료 후에도 삭제되지 않음 |
| 기대 결과 | 만료된 토큰은 주기적으로 삭제 |
| 실제 결과 | `RefreshTokenRepository.deleteExpired()` 쿼리는 만들어져 있지만 **어디서도 호출하지 않음** → 테이블이 계속 커짐 |
| 원인 | 정리 작업(스케줄러) 누락 |
| 수정 내역 | [`RefreshTokenCleanupJob`](../../backend/src/main/java/com/bapmeokja/api/auth/service/RefreshTokenCleanupJob.java) 추가 (매일 04:00 KST, `app.jwt.cleanup-cron`으로 변경 가능), [`SchedulingConfig`](../../backend/src/main/java/com/bapmeokja/api/config/SchedulingConfig.java)로 스케줄링 활성화 |
| 회귀 테스트 | `RefreshTokenCleanupJobTest.deletesTokensExpiredAtCurrentTime` |
| 확인 | 단위 테스트 통과, 서버 재기동 후 통합·시스템 테스트 전체 통과 |

| `PUT /fridge/ingredients/{id}` | 냉장고 재료 수량 수정 (현재 삭제·추가만 가능) |
| `PUT /community/posts/{id}` | 게시글 수정 |

백엔드 동작은 통합·시스템 테스트로 확인했습니다. 담당: 프론트엔드.
