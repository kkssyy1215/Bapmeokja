## 2. 방법

시스템 테스트는 **실제 사용자가 앱에서 하는 순서 그대로** 여러 기능을 이어서 실행하고, 앞 단계의 결과가 다음 화면(홈·캘린더·통계·추천)의 데이터에 맞게 반영되는지 확인합니다. 예를 들어 "사진 기록 → 양 수정 → 저장"을 한 뒤 홈 대시보드 섭취량, 캘린더 표시, 일간 통계 값이 모두 저장한 값과 같은지 검증합니다.

- 자동화: `scripts/qa/system_test.py`가 앱이 호출하는 API 순서대로 시나리오를 실행합니다.
- 화면 확인: 주요 흐름(로그인 → 홈 → 기록 → 통계 → 추천 → 커뮤니티 → 냉장고, 직접 입력 저장)은 Expo 웹 화면에서도 따로 확인했습니다. 자세한 내용은 [통합 테스트 결과서 3장](03-통합-테스트-결과서.md#3-front--back-연동-테스트)에 있습니다.

## 4. 시나리오 상세

### ST-01 신규 사용자 가입부터 홈 화면 진입까지
**흐름**: 아이디·이메일·닉네임 중복 확인 → 회원가입 → 자동 로그인 → 신체정보 입력 → 홈
**핵심 검증**: 가입 직후 `isNewUser=true`라서 온보딩으로 이동하고, 신체정보 입력 후 계산된 목표 칼로리(1,900 kcal)가 홈 대시보드 목표와 같으며, 재로그인 시 `isNewUser=false`로 바뀝니다.

### ST-02 사진으로 식단 기록 후 홈·캘린더·통계 반영
**흐름**: 사진 업로드 → 분석 결과 확인 → 첫 음식 양을 1.5배로 수정 → 저장 → 홈 / 캘린더 / 오늘 식단 / 일간 통계
**핵심 검증**: 수정한 값으로 계산한 총 칼로리가 저장 응답·홈 섭취량·일간 통계에 **같은 값으로** 표시됩니다. 캘린더에 오늘 날짜가 표시됩니다.

### ST-03 직접 입력 기록의 수정·삭제
**흐름**: 음식 검색('달걀') → 아침으로 기록 → 저녁·2배 양으로 수정 → 상세 확인 → 삭제
**핵심 검증**: 수정 내용(끼니, 칼로리 2배)이 상세 화면에 반영되고, 삭제 후 목록이 0건, 홈 섭취량이 0으로 돌아갑니다.

### ST-04 기록 누적 후 기간별 통계·AI 피드백 확인
**흐름**: 아침 350 + 점심 650 + 저녁 550 kcal 기록 → 일간·주간·월간 통계 → 일간·주간·월간 피드백
**핵심 검증**: 세 기간 통계 모두 합계 1,550 kcal를 반영하고, 피드백 문구가 생성됩니다.

### ST-05 남은 영양 기반 외식 추천과 주변 매장 찾기
**흐름**: 점심 기록 → 외식 예산 11,000원 설정 → 추천 메인 → 외식 카테고리 추천 → 메뉴 목록·상세 → 주변 매장(동의 전/후)
**핵심 검증**: 추천 메인에 섭취 500 kcal와 예산이 반영되고, 예산을 따로 넣지 않으면 설정 예산(11,000원)이 적용됩니다. 위치 동의 전에는 403으로 막히고, 동의 후에는 강남역 반경 1km 매장이 조회됩니다.

### ST-06 냉장고 재료로 집밥 추천 → 레시피 → 장보기
**흐름**: 재료 3개 등록(닭가슴살은 오늘 만료) → 목록 → 남은 재료 추천 → 집밥 추천 → 레시피 목록·상세 → 장보기 → 계란 수량 수정 → 닭가슴살 삭제
**핵심 검증**: 유통기한 임박 표시, 레시피 상세의 재료·대체재·조리 단계, 최종 냉장고 상태(계란 2개, 닭가슴살 없음).

### ST-07 커뮤니티 글 작성·댓글·좋아요·삭제 (사용자 2명)
**흐름**: A가 사진 영양 추정 → 사진과 함께 글 작성 → B가 목록·상세·이미지 확인 → 댓글·좋아요 → A가 카운트 확인 → B가 A의 글 수정 시도 → A 수정 → B 댓글 삭제 → A 글 삭제
**핵심 검증**: 업로드 이미지가 실제로 열리고, 댓글·좋아요 수가 작성자 화면에 반영됩니다. 남의 글 수정은 403으로 막히고, 삭제된 글은 404가 됩니다.

### ST-08 설정: 프로필·알림·비밀번호 변경·탈퇴
**흐름**: 감량 목표로 프로필 수정 → 홈 목표 칼로리 확인 → 알림 설정 → 비밀번호 변경 → 기존/새 비밀번호 로그인 → 탈퇴
**핵심 검증**: 목표를 감량으로 바꾸면 홈 목표 칼로리가 낮아집니다. 비밀번호 변경 후 기존 비밀번호는 401이고, 탈퇴한 계정은 로그인할 수 없습니다.

### ST-09 세션 유지·만료·로그아웃 보안 흐름
**흐름**: 토큰 없이 접근 → refresh로 재발급 → 새 토큰으로 API 사용 → 이전 refresh 재사용 → 로그아웃 → 로그아웃 후 refresh
**핵심 검증**: refresh token은 한 번 쓰면 폐기되어(회전), 탈취된 이전 토큰을 재사용할 수 없습니다. 로그아웃하면 refresh도 무효가 됩니다.
