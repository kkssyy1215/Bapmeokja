# 배포 가이드

## 현재 상태와 선택지

| 방법 | 비용 | 필요한 것 | 비고 |
|---|---|---|---|
| **로컬 Docker** | 무료 | Docker | 개발·같은 와이파이 시연. PC가 켜져 있어야 함 |
| **Vercel + Aiven** (시연용, 현재 선택) | 무료 | Vercel, Aiven 계정 | 어디서나 접속. 아래 제한 참고 |
| **GHCR 이미지 + 무료 서버** | 무료 조건 있음 | 클라우드 계정(결제수단 등록) | 어디서나 접속, 사진 유지 |

무료 서버 조건은 자주 바뀌므로 가입 전에 공식 페이지에서 확인하세요.
- **AWS 프리 플랜:** 신규 계정, 크레딧 100~200달러, 최대 6개월. 끝나면 계정이 닫히므로 데이터를 백업해야 합니다.
- **Oracle Always Free:** 기간 제한 없음. ARM 2 OCPU·12GB로 축소된 것으로 보도됨. 지역에 따라 서버 생성이 안 될 수 있습니다.

## Vercel + Aiven 배포 (시연용)

저장소 권한과 상관없이 내 PC에서 CLI로 배포합니다. 서버(`backend/Dockerfile.vercel`)와 웹 화면(`vercel.json`)이 각각 Vercel 프로젝트가 됩니다.

1. [Aiven](https://aiven.io/free-tier)에 가입하고 무료 MySQL 서비스를 만듭니다. 서비스 화면에서 **Service URI**를 복사합니다.
2. 설정 파일을 만들고 `AIVEN_SERVICE_URI=` 뒤에 붙여 넣습니다. 이 파일은 Git에 올라가지 않습니다.

```bash
cp deploy.vercel.example .env.vercel
```

3. [Vercel](https://vercel.com/signup)에 가입하고 로그인합니다.

```bash
npx vercel login
```

4. 배포합니다. `.env`의 `GEMINI_API_KEY`도 함께 등록됩니다.

```bash
./scripts/deploy/vercel-deploy.sh
```

끝나면 웹 주소와 서버 주소가 출력되고 `.vercel-urls`에 저장됩니다. 다시 실행하면 재배포됩니다.

### 이 구성의 제한

| 항목 | 내용 | 시연 대응 |
|---|---|---|
| **Aiven 자동 꺼짐** | 활동이 없으면 무료 DB가 꺼짐 (꺼지기 전 알림) | **발표 전에 콘솔에서 켜져 있는지 확인** |
| **서버 절전** | 요청이 5분 없으면 꺼지고, 다음 요청에서 다시 시작 | 발표 직전에 사이트를 한 번 열어 깨워 두기 |
| **업로드 4.5MB** | 넘으면 Vercel이 413으로 거절 | 식단 사진은 앱이 줄여서 올림. 커뮤니티 사진은 작은 파일 사용 |
| **사진 유지 안 됨** | 서버가 다시 시작되면 올린 사진이 사라짐 (DB 데이터는 유지) | 시연 중에 올린 사진은 그 자리에서 사용 |
| **Vercel 컨테이너 베타** | 정식 기능이 아니라 동작이 바뀔 수 있음 | 시연 전에 미리 확인 |
| **만료 토큰 정리, 요청 제한** | 서버가 꺼져 있으면 정리 안 됨, 제한은 인스턴스별 | 시연 규모에서는 영향 작음 |

로컬 재현 결과(CPU 1개·메모리 2GB·읽기 전용 디스크, TLS·기본키 필수 MySQL): 통합 136/136, 시스템 9/9, 탐색 40/40, 재시작 약 7~8초. 

실제 배포 확인(2026-11-03): 웹 `https://bapmeokja-web.vercel.app`, 서버 `https://bapmeokja-api.vercel.app`. 서버 상태 UP, 웹 주소 CORS 허용, 다른 주소 거부(403), 웹에서 서버를 거쳐 DB 조회까지 정상, 잠든 서버의 첫 응답 약 11~14초. 깨어나는 순간의 상태 확인은 503이 한 번 나온 적이 있으나 바로 UP으로 돌아옴. 회원가입·로그인·사진 분석은 실제 주소에서 아직 확인하지 않았습니다.

### 배포 구성에서 주의할 점

스크립트가 아래 항목을 자동으로 처리합니다.

- **DB 테이블 생성은 내 PC에서 실행**: Vercel은 약 27초 안에 포트가 열리지 않으면 인스턴스를 끝냅니다. 테이블 생성 도중 끝나면 스키마가 반만 남으므로, 로컬 Docker로 먼저 끝내고 배포된 서버에서는 `SPRING_FLYWAY_ENABLED=false`로 끕니다. Docker가 실행 중이어야 합니다.
- **앱 전용 DB**: Aiven `defaultdb` 대신 `bapmeokja` 데이터베이스를 씁니다.
- **서버 리전 `sin1`**: DB가 싱가포르에 있어 서버도 같은 곳에서 실행합니다. `vercel.json`의 `regions`는 컨테이너에 적용되지 않아 프로젝트 설정으로 바꿉니다.
- **서버는 `backend` 폴더 안에서 배포**: `--cwd backend`로 실행하면 루트의 웹용 `vercel.json`이 함께 전달되어 모든 요청이 `/`로 바뀝니다.

## 1. 로컬 실행

```bash
cp .env.example .env
```

```bash
docker compose up -d --build
```

- 상태 확인: `http://localhost:8080/actuator/health`
- API 문서: `http://localhost:8080/swagger-ui.html`
- 앱을 서버에 연결: `.env.local`의 `EXPO_PUBLIC_USE_MOCKS`를 `false`로 바꾸고 `npx expo start --clear`로 실행. 화면의 '서버 데이터' 배지로 확인합니다.

## 2. 실제 AI 사진 분석 켜기 (선택)

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 API 키를 발급합니다.
2. `.env`에 `GEMINI_API_KEY=발급받은_키`를 넣습니다. 키는 저장소에 올리지 마세요(`.env`는 git 제외 대상).
3. `docker compose up -d`로 재시작합니다. 로그에 `Food photos are analyzed with Gemini model`이 보이면 적용된 것입니다.

키가 없으면 파일명 기반 시연용 분석기로 동작합니다. 무료 등급은 입력 내용이 Google의 제품 개선에 쓰일 수 있고 호출량 제한이 있으니, 조건을 [요금 페이지](https://ai.google.dev/gemini-api/docs/pricing)에서 확인하세요.

## 3. 서버 배포 (Linux VM + Docker)

1. 서버에 Docker를 설치하고 8080 포트만 엽니다. DB 포트는 열지 않습니다.
2. 저장소의 `docker-compose.prod.yml`을 서버에 복사합니다.
3. 같은 폴더에 `.env.prod`를 만듭니다.

```bash
MYSQL_PASSWORD=임의의_긴_비밀번호
MYSQL_ROOT_PASSWORD=임의의_긴_비밀번호
JWT_SECRET=32바이트_이상_임의_문자열
CORS_ALLOWED_ORIGINS=https://웹사이트_주소
GEMINI_API_KEY=
```

4. 실행합니다. 이미지는 `main` 브랜치 CI가 올린 것을 받습니다.

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
```

5. 앱의 `EXPO_PUBLIC_API_URL`을 `http://서버주소:8080/v1`로 바꿉니다. 웹이나 스토어 배포에는 HTTPS 주소가 필요하므로 도메인과 리버스 프록시(Caddy, Nginx)를 앞에 둡니다.

## 운영 프로필이 하는 일

`SPRING_PROFILES_ACTIVE=prod`일 때 적용됩니다 (`application-prod.yml`).
- `JWT_SECRET`, DB 접속 정보, CORS 주소가 없으면 서버가 시작되지 않습니다.
- Swagger를 끕니다. 필요하면 `SWAGGER_ENABLED=true`로 켭니다.
- 요청 횟수 제한을 항상 켭니다 (인증 분당 30회, 사진 분석 분당 10회, IP 기준).

## 업데이트와 백업

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod pull
```

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d
```

데이터는 Docker 볼륨 `mysql-data`, `upload-data`에 있습니다. DB 백업은 다음과 같이 합니다.

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" bapmeokja' > backup.sql
```

## 알려진 제한

- 요청 제한 카운터는 서버 메모리에 있어서 재시작하면 초기화되고, 서버 한 대 기준입니다.
- 서버 앞에 프록시가 없으면 `X-Forwarded-For`를 위조해 제한을 우회할 수 있으므로, 프록시를 쓸 때 그 헤더를 프록시가 덮어쓰도록 설정하세요.
- 사진은 서버 디스크에 저장됩니다. 서버를 옮길 때 `upload-data` 볼륨도 함께 옮겨야 합니다.
